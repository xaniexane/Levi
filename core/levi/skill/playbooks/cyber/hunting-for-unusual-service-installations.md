## Purpose

Windows services run with SYSTEM privileges, start automatically, and
blend into a large legitimate service population — ideal persistence for
attackers. This playbook covers hunting malicious service installations
through service-creation events, ImagePath analysis, and baseline
diffing.

## When to use

- Post-compromise persistence sweeps.
- Triaging service-creation alerts (7045, 4697).
- Hunting for privilege-escalation via service abuse.
- Validating service-inventory monitoring.

## Prerequisites

- System log event 7045 (service installed) and Security log 4697
  collected centrally.
- Fleet service inventory with binary paths, signers, and start types.
- Gold-image service baselines per host role.
- Change records for legitimate software deployments.

## Procedure

1. **Monitor service-creation events.** Alert on 7045/4697 events,
   capturing the service name, ImagePath, service type, start type,
   and the account it runs as. Services installed outside change
   windows are the primary hunting surface.
2. **Analyze the ImagePath.** The binary path and arguments reveal
   intent: services pointing to temp directories, user-writable paths,
   script interpreters, or with encoded arguments are high priority.
   Verify the target binary's signer and hash.
3. **Check the service account.** Services running as LocalSystem with
   suspicious binaries are the classic malicious pattern. Also review
   services configured with domain credentials — they expose those
   credentials and indicate the installer's privilege level.
4. **Diff against baselines.** Compare each host's service inventory to
   its role baseline and fleet prevalence. Unique, recently created,
   unsigned services are the top triage tier.
5. **Correlate the installation.** Tie each new service to its creator:
   which process/user installed it (4688/4697 subject fields), and
   what happened around installation time. Attacker-installed services
   cluster with intrusion activity; vendor-installed ones cluster with
   deployment tickets.
6. **Look for service-abuse variants.** Beyond new services, hunt:
   ImagePath tampering on existing services (bin-path modification),
   services with failure-actions configured for persistence
   re-establishment, and driver-services (.sys) for kernel-level
   persistence.
7. **Remediate completely.** Stop and delete malicious services, remove
   their binaries, verify via re-enumeration, and check for companion
   persistence. For services using domain credentials, rotate those
   credentials.
8. **Deploy durable detections.** Alert on 7045/4697 outside change
   windows, on services with user-writable ImagePaths, and on
   bin-path modifications to existing services.

## Expected outputs

- Service-creation findings with ImagePath and account analysis.
- Baseline diffs with triage dispositions.
- Installation attribution per malicious service.
- Verified remediation records.
- Service-monitoring detections with tuning notes.

## Pitfalls

- Legitimate software installs many services — change-record
   integration is essential to avoid alert fatigue.
- Service names are easily spoofed to look legitimate — analyze the
   ImagePath and binary, not the display name.
- Driver-services require a different response (kernel persistence) —
   classify service type before remediating.
- Deleting the service but leaving the binary (or a re-creating
   scheduled task) — verify holistically and reboot-check.
- 7045 events can be generated by legitimate updaters at scale —
   baseline per software title.
