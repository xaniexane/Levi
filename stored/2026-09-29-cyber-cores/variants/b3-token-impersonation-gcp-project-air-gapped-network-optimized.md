# Token Impersonation Defense for GCP Projects in Air-Gapped Networks (Optimized Maturity)

## Purpose

Attackers steal or duplicate Windows access tokens to act as another user — often SYSTEM — without knowing any password. EDR sees odd parent/child relationships and token-privilege enabling that legitimate software rarely performs. Applies to GCP Projects in Air-Gapped Networks at Optimized maturity.

## When to use

- Processes enabling SeDebugPrivilege or SeImpersonatePrivilege outside of known admin tooling, or unexpected token duplication API sequences in EDR telemetry.
- A low-privilege process spawning children as SYSTEM or as another logged-on user without a legitimate service path.
- Named-pipe impersonation patterns (PrintSpooler-style) from non-printer processes.
- Lens: Best telemetry: Cloud Audit Logs (Admin Activity + Data Access) + Security Command Center + VPC flow logs. Local SIEM/log collector inside the enclave (no cloud shipping); removable-media transfer logs.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to Strict allowlisting logs: every binary execution recorded, since the set is small and known.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in Cloud Audit Logs: setIamPolicy, storage.setIamPermissions, compute inserts, and console logons and Security Command Center findings; Forseti/Config Validator drift reports where deployed; run `gcloud logging read 'protoPayload.methodName:"SetIamPolicy"' --limit 20 --format='table(timestamp, protoPayload.authenticationInfo.principalEmail, resourceName)'` then `gcloud scc findings list organizations/$ORG_ID --filter='state="ACTIVE"' --limit 15`.
3. **Analyze.** Trace the token source: which process's token was stolen, and did that source process itself get compromised first? Then: Check what the impersonated context accessed — file, registry, and network actions taken as the victim identity.
4. **Contain and harden.** Remove SeImpersonatePrivilege from service accounts that do not need it; patch print-spooler-class vulnerabilities promptly. Asset layer: Organization policies: no public buckets, no default SA use, OS Login on; deny unapproved APIs. Environment layer: Data diodes or strictly controlled one-way transfers; media sanitization procedures for anything crossing.
5. **Document and improve.** Feed incident lessons back into detection-as-code within one sprint — the playbook is a living document, not a PDF. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Assuming token theft requires admin — some impersonation primitives work from lower privilege.
- Missing that a stolen token can be replayed on OTHER hosts via remote authentication.
