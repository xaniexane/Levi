# DNS Fast-Flux Defense for SaaS Applications in Hybrid Cloud (Foundational Maturity)

## Purpose

Fast-flux networks rotate DNS answers across many compromised hosts every few minutes, making malicious infrastructure hard to takedown. Defenders detect the flux pattern itself: low TTLs, high answer churn, and geographically scattered A records. Applies to SaaS Applications in Hybrid Cloud at Foundational maturity.

## When to use

- DNS answers with TTLs under 300 seconds rotating across dozens of IPs in unrelated ASNs and countries for a single domain.
- Short-lived domains (registered days ago) resolving to residential or compromised-server IPs with no legitimate business relationship.
- Endpoint connections to flux domains correlating with malware detonations or phishing kit infrastructure.
- Lens: Best telemetry: SaaS audit logs (admin + user activity) streamed to SIEM + SSO logs. Unified SIEM ingesting both on-prem syslog and cloud audit trails with identity correlation across both.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to Conditional-access and network logs covering the interconnect (ExpressRoute/Direct Connect/VPN).

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in Admin audit log (settings changes, user provisioning, sharing changes) and User activity logs: file access, downloads, external sharing events; run `# conceptually (SaaS APIs differ):` then `saas-cli audit log --category admin --last 7d --format table | head -25`.
3. **Analyze.** Profile the flux: record TTL, unique IPs per hour, ASN/country spread, and name-server patterns to fingerprint the specific flux service or kit. Then: Pivot from the domain to find sibling infrastructure: shared name servers, registration patterns, and certificate overlaps.
4. **Contain and harden.** DNS response policy zones (RPZ) blocking confirmed flux domains, plus alerting on sub-300s TTL answers at the resolver. Asset layer: SSO with MFA enforced, SCIM provisioning, least-privilege roles, external-sharing restricted. Environment layer: Consistent identity (single IdP) across on-prem and cloud; no parallel credential stores.
5. **Document and improve.** Define one escalation trigger in advance (e.g., confirmed credential theft, more than 3 hosts) that moves the case from analyst to incident commander. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Blocking individual flux IPs — they churn in minutes; block the domain pattern and the detection logic instead.
- Confusing legitimate CDN behavior (low TTL, many IPs) with flux; require the ASN-scatter plus short-domain-age combination.
