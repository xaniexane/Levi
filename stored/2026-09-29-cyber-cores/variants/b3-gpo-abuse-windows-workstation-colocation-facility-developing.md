# Group Policy Abuse Defense for Windows Workstations in Colocation Facilities (Developing Maturity)

## Purpose

Group Policy deploys to every machine in scope — including attacker-planted scheduled tasks, scripts, and software. A malicious GPO is a domain-wide persistence and execution platform; monitor GPO changes like code deployments. Applies to Windows Workstations in Colocation Facilities at Developing maturity.

## When to use

- 5136/5137 directory-service changes creating or modifying GPOs, especially new immediate scheduled tasks, startup scripts, or software installation policies.
- SYSVOL replication of unexpected scripts/executables, or GPO version number jumps without a change ticket.
- Mass host behavior change correlating with GP refresh cycles (new persistence appearing fleet-wide simultaneously).
- Lens: Best telemetry: Sysmon + EDR + PowerShell script-block logging forwarded to the SIEM. Customer-owned network taps and logging (the colo provider's logs are out of scope — verify contractually).

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to Badge/physical access logs from the facility correlated with remote-hand ticket times.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in Security event log (4624/4625 logons, 4688 process creation, 7045 service installs) and Sysmon operational log and PowerShell operational log (4104 script blocks); run `Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625} -MaxEvents 50 | Format-List TimeCreated, @{n='TargetUser';e={$_.Properties[5].Value}}, @{n='SourceIP';e={$_.Properties[19].Value}}` then `autorunsc64.exe -accepteula -a * -c -h -s -t | findstr /v "Microsoft Corporation"`.
3. **Analyze.** Inspect the GPO's full settings and linked scripts; determine the deployment scope (which OUs) to size the affected fleet. Then: Check GPO backup/version history to find when the malicious change was introduced and by whom.
4. **Contain and harden.** Restrict GPO edit rights to a break-glass group, require change tickets, and alert on any GPO modification in real time. Asset layer: Application allowlisting (WDAC/AppLocker) and LSA Protection + Credential Guard enabled. Environment layer: Locked cabinets, private cages, and escort policies for remote hands.
5. **Document and improve.** Assign RACI for each procedure step (who detects, who contains, who communicates) and rehearse it quarterly. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Deleting the malicious GPO without removing the persistence it already deployed to thousands of hosts.
- Missing GPO-based deployment because you hunted only local persistence mechanisms.
