# Process Injection Defense for Kubernetes Clusters in Remote Workforce (Optimized Maturity)

## Purpose

Malware hides inside legitimate processes via injection (CreateRemoteThread, APC, process hollowing), blending with normal activity. Memory-focused detection — EDR telemetry and targeted memory analysis — is the answer; disk forensics alone misses it. Applies to Kubernetes Clusters in Remote Workforce at Optimized maturity.

## When to use

- EDR alerts on cross-process memory writes (CreateRemoteThread, NtQueueApcThread) from unusual sources, or hollowed processes (image path mismatches the in-memory PE).
- Legitimate processes (explorer, svchost) making unexpected network connections or spawning children they never normally do.
- Sysmon event 8 (CreateRemoteThread) and event 10 (ProcessAccess) with suspicious granted-access masks.
- Lens: Best telemetry: Kubernetes audit logs + container runtime logs + admission-controller denials. EDR on every endpoint as the primary sensor (no corporate network tap for remote hosts).

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to VPN/ZTNA access logs and SaaS/IdP sign-in logs as the network-visibility substitute.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in API-server audit log (who created pods/bindings/secrets, from where) and Kubelet/container runtime logs and image pull histories per node; run `kubectl audit2rbac --filename=audit.log 2>/dev/null | head; kubectl get clusterrolebindings -o wide | head -20` then `kubectl get pods -A -o json | python3 -c "import json,sys; [print(p['metadata']['namespace'], p['metadata']['name'], p['spec'].get('hostNetwork'), p['spec'].get('hostPID')) for p in json.load(sys.stdin)['items']]" | head -30`.
3. **Analyze.** Capture process memory before killing anything; extract the injected payload for family identification. Then: Trace the injector: which process performed the injection and how did IT get compromised (the delivery chain).
4. **Contain and harden.** EDR with behavioral blocking on injection primitives; application control to prevent the initial injector from running. Asset layer: Least-privilege RBAC, Pod Security Standards enforced, no privileged pods, image signing/verification. Environment layer: Zero-trust access: device compliance + MFA per application, not per network.
5. **Document and improve.** Feed incident lessons back into detection-as-code within one sprint — the playbook is a living document, not a PDF. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Killing the host process without capturing memory — the payload exists only in RAM and the evidence is gone.
- Whitelisting the injected process because its NAME is legitimate; verify the in-memory image, not the filename.
