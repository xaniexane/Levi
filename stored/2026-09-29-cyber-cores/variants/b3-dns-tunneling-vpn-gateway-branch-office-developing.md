# DNS Tunneling Defense for VPN Gateways in Branch Offices (Developing Maturity)

## Purpose

DNS tunneling smuggles data or C2 inside DNS queries, abusing a protocol almost every network allows outbound. Detection hinges on query shape (length, entropy, volume, record types), not on blocklists. Applies to VPN Gateways in Branch Offices at Developing maturity.

## When to use

- Long, high-entropy subdomains (often 50+ chars) in DNS logs, unusual record types (TXT, NULL) at volume, or a single host generating thousands of queries to one domain.
- Beacon-like regularity in query timing to an obscure domain, or DNS queries for domains registered within the last 30 days.
- Responses with abnormally large TXT records relative to the query — data coming back down the tunnel.
- Lens: Best telemetry: authentication logs + session logs (user, IP, bytes, duration) + gateway patch state. SD-WAN/branch firewall logs forwarded centrally; local DHCP/DNS logs for device attribution.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to NAC or port-level logs identifying which device was on which port during the incident.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in VPN auth logs (success/failure per user with source IPs), session tables with data volumes and Gateway admin audit log and firmware/patch version; client version inventory; run `# conceptually (vendor CLIs differ):` then `show vpn-sessiondb detail anyconnect | grep -E 'Username|Assigned IP|Login Time'`.
3. **Analyze.** Decode a sample of tunneled queries/responses in a sandbox to determine direction and content: C2 instructions, exfiltrated data, or both. Then: Identify patient zero by earliest query timestamp, then hunt laterally: tunneling tools are often deployed to multiple hosts.
4. **Contain and harden.** Force all DNS through logged, filtered resolvers; block direct port-53 egress from endpoints and alert on non-standard DNS ports. Asset layer: MFA on every VPN profile, device posture checks before granting access, gateway firmware patched urgently. Environment layer: Standardized branch firewall policy deployed as code; no local admin exceptions.
5. **Document and improve.** Assign RACI for each procedure step (who detects, who contains, who communicates) and rehearse it quarterly. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Blocking the domain without finding the implant — the attacker rotates domains faster than you blocklist.
- Ignoring DNS over HTTPS (DoH): tunneled traffic inside DoH is invisible to passive DNS monitoring — log at the endpoint.
