# Token Impersonation Defense for Code Repositories in On-Premises Datacenter (Defined Maturity)

## Purpose

Attackers steal or duplicate Windows access tokens to act as another user — often SYSTEM — without knowing any password. EDR sees odd parent/child relationships and token-privilege enabling that legitimate software rarely performs. Applies to Code Repositories in On-Premises Datacenter at Defined maturity.

## When to use

- Processes enabling SeDebugPrivilege or SeImpersonatePrivilege outside of known admin tooling, or unexpected token duplication API sequences in EDR telemetry.
- A low-privilege process spawning children as SYSTEM or as another logged-on user without a legitimate service path.
- Named-pipe impersonation patterns (PrintSpooler-style) from non-printer processes.
- Lens: Best telemetry: push/audit logs + secret-scanning alerts + branch-protection change history. Full network tap/SPAN coverage at core and distribution layers feeding IDS and full-packet capture.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to Centralized syslog from all infrastructure with NTP-synced timestamps for cross-device correlation.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in Push logs (who pushed what to which branch), force-push and history-rewrite records and Secret-scanning and code-scanning alerts with their resolution state; run `git log --since='7 days ago' --format='%h %an %ad %s' --date=short | head -30` then `git log --all --diff-filter=A -- '*secret*' '*credential*' '*key*' --format='%h %an %s' | head -20`.
3. **Analyze.** Trace the token source: which process's token was stolen, and did that source process itself get compromised first? Then: Check what the impersonated context accessed — file, registry, and network actions taken as the victim identity.
4. **Contain and harden.** Remove SeImpersonatePrivilege from service accounts that do not need it; patch print-spooler-class vulnerabilities promptly. Asset layer: Branch protection with required reviews, signed commits, push protection for secrets. Environment layer: Physical access controls with badge logs correlatable to logical access during investigations.
5. **Document and improve.** Map each detection signal to the relevant MITRE technique and confirm coverage in the detection engineering backlog. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Assuming token theft requires admin — some impersonation primitives work from lower privilege.
- Missing that a stolen token can be replayed on OTHER hosts via remote authentication.

## References

- MITRE ATT&CK: T1134 (Privilege Escalation: Access Token Manipulation)
