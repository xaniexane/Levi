# Container Escape Defense for Kubernetes Clusters in Branch Offices (Foundational Maturity)

## Purpose

A compromised container breaks out to the host via privileged mode, hostPath mounts, or kernel exploits — turning one application breach into full node control. Harden the container boundary and monitor for escape primitives. Applies to Kubernetes Clusters in Branch Offices at Foundational maturity.

## When to use

- Containers running privileged or with hostPath mounts to sensitive host paths, especially created outside normal deployments.
- Host-level processes spawned by container runtimes, or unexpected writes to host paths from container contexts.
- Kernel exploit artifacts or abuse of host namespaces (nsenter-style) inside container workloads.
- Lens: Best telemetry: Kubernetes audit logs + container runtime logs + admission-controller denials. SD-WAN/branch firewall logs forwarded centrally; local DHCP/DNS logs for device attribution.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to NAC or port-level logs identifying which device was on which port during the incident.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in API-server audit log (who created pods/bindings/secrets, from where) and Kubelet/container runtime logs and image pull histories per node; run `kubectl audit2rbac --filename=audit.log 2>/dev/null | head; kubectl get clusterrolebindings -o wide | head -20` then `kubectl get pods -A -o json | python3 -c "import json,sys; [print(p['metadata']['namespace'], p['metadata']['name'], p['spec'].get('hostNetwork'), p['spec'].get('hostPID')) for p in json.load(sys.stdin)['items']]" | head -30`.
3. **Analyze.** Determine the escape primitive: misconfiguration (privileged, hostPath, hostPID) versus kernel CVE — the fix differs. Then: Assess node compromise: if escaped, the node is hostile — cordon, drain, and rebuild it; do not trust in-place cleaning.
4. **Contain and harden.** Never run privileged containers; drop capabilities, use read-only root filesystems, and enforce via admission controllers (OPA/Kyverno). Asset layer: Least-privilege RBAC, Pod Security Standards enforced, no privileged pods, image signing/verification. Environment layer: Standardized branch firewall policy deployed as code; no local admin exceptions.
5. **Document and improve.** Define one escalation trigger in advance (e.g., confirmed credential theft, more than 3 hosts) that moves the case from analyst to incident commander. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Rebuilding the container while the compromised node keeps serving the attacker's workloads.
- Assuming non-privileged means safe — hostPath mounts and capabilities can be equally fatal.

## References

- MITRE ATT&CK: T1611 (Escape to Host)
