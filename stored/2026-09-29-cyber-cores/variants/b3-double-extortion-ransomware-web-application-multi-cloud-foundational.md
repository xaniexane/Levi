# Double-Extortion Ransomware Defense for Web Applications in Multi-Cloud (Foundational Maturity)

## Purpose

Data is exfiltrated BEFORE encryption, so the attacker can leak it even if you restore from backups. The investigation must answer what was stolen, not just what was encrypted — breach notification clocks start on exfiltration. Applies to Web Applications in Multi-Cloud at Foundational maturity.

## When to use

- Large outbound transfers (tens of GB) to cloud storage, file shares, or anonymized endpoints in the days before encryption, often via rclone, MEGAsync, or custom tooling.
- Staging directories with archived/renamed sensitive data (databases, file shares zipped) and data-leak-site monitoring hits for your organization name.
- The ransom note references specific stolen files or threatens publication with a countdown timer.
- Lens: Best telemetry: app audit logs (with authenticated identity) + WAF logs + structured access logs. Cloud-agnostic SIEM normalizing AWS CloudTrail, Azure Activity Log, and GCP Audit Logs into one schema.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to CSPM coverage across all clouds with consistent misconfiguration alerting.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in Application audit log: who did what to which object, with session IDs and source IPs and WAF block logs and anomaly scores; web-server access/error logs around the incident; run `grep -E ' 4[0-9]{2} | 5[0-9]{2} ' /var/log/nginx/access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -15` then `journalctl -u myapp --since '2 hours ago' | grep -iE 'error|unauthor|exception' | tail -30`.
3. **Analyze.** Quantify the exfil: source directories, file types, record counts, and whether regulated data (PII, PHI, card data) was included — this drives notification obligations. Then: Preserve exfiltration logs (proxy, firewall, DLP, cloud audit) as evidence; they are also the proof of what did and did not leave.
4. **Contain and harden.** DLP egress policies on sensitive data stores plus alerting on bulk archive creation and large outbound transfers. Asset layer: Authorization checks on every object reference, output encoding, parameterized queries, secure session handling. Environment layer: Federated identity across clouds from one IdP; consistent tagging and logging standards per cloud.
5. **Document and improve.** Define one escalation trigger in advance (e.g., confirmed credential theft, more than 3 hosts) that moves the case from analyst to incident commander. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Declaring victory after restoring from backup while stolen data sits on a leak site — the extortion continues.
- Starting the notification clock at encryption time instead of at first confirmed exfiltration.

## References

- MITRE ATT&CK: T1486 + T1048 (Exfiltration Over Alternative Protocol)
- Vendor logging and hardening baselines for Web Applications; Federated identity across clouds from one IdP; consistent tagging and logging standards per cloud.
