# DNS Tunneling Defense for Active Directory Domain Controllers in On-Premises Datacenter (Managed Maturity)

## Purpose

DNS tunneling smuggles data or C2 inside DNS queries, abusing a protocol almost every network allows outbound. Detection hinges on query shape (length, entropy, volume, record types), not on blocklists. Applies to Active Directory Domain Controllers in On-Premises Datacenter at Managed maturity.

## When to use

- Long, high-entropy subdomains (often 50+ chars) in DNS logs, unusual record types (TXT, NULL) at volume, or a single host generating thousands of queries to one domain.
- Beacon-like regularity in query timing to an obscure domain, or DNS queries for domains registered within the last 30 days.
- Responses with abnormally large TXT records relative to the query — data coming back down the tunnel.
- Lens: Best telemetry: forwarded Security logs (4768/4769/4771/4662/4720/4732/4724/5136) + AD replication monitoring. Full network tap/SPAN coverage at core and distribution layers feeding IDS and full-packet capture.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to Centralized syslog from all infrastructure with NTP-synced timestamps for cross-device correlation.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in Security log Kerberos events (4768 TGT requests, 4769 service tickets, 4771 pre-auth failures) and Directory-service change events (5136/5137) and replication metadata (repadmin /showobjmeta); run `repadmin /showrepl | Select-String -Pattern 'error|fail' -Context 2` then `Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4769} -MaxEvents 200 | Group-Object {$_.Properties[0].Value} | Sort-Object Count -Descending | Select-Object -First 10 Name, Count`.
3. **Analyze.** Decode a sample of tunneled queries/responses in a sandbox to determine direction and content: C2 instructions, exfiltrated data, or both. Then: Identify patient zero by earliest query timestamp, then hunt laterally: tunneling tools are often deployed to multiple hosts.
4. **Contain and harden.** Force all DNS through logged, filtered resolvers; block direct port-53 egress from endpoints and alert on non-standard DNS ports. Asset layer: Tier-zero isolation: DCs on dedicated hosts, no browsing/email, admin access via PAW/jump host only. Environment layer: Physical access controls with badge logs correlatable to logical access during investigations.
5. **Document and improve.** Pre-authorize low-risk containment (host isolation, session revoke, password reset) in the SOAR playbook with full audit logging. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Blocking the domain without finding the implant — the attacker rotates domains faster than you blocklist.
- Ignoring DNS over HTTPS (DoH): tunneled traffic inside DoH is invisible to passive DNS monitoring — log at the endpoint.
