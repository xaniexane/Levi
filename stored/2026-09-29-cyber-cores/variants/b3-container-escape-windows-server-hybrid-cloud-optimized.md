# Container Escape Defense for Windows Servers in Hybrid Cloud (Optimized Maturity)

## Purpose

A compromised container breaks out to the host via privileged mode, hostPath mounts, or kernel exploits — turning one application breach into full node control. Harden the container boundary and monitor for escape primitives. Applies to Windows Servers in Hybrid Cloud at Optimized maturity.

## When to use

- Containers running privileged or with hostPath mounts to sensitive host paths, especially created outside normal deployments.
- Host-level processes spawned by container runtimes, or unexpected writes to host paths from container contexts.
- Kernel exploit artifacts or abuse of host namespaces (nsenter-style) inside container workloads.
- Lens: Best telemetry: Security log with advanced audit policy + Sysmon + service-install monitoring. Unified SIEM ingesting both on-prem syslog and cloud audit trails with identity correlation across both.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to Conditional-access and network logs covering the interconnect (ExpressRoute/Direct Connect/VPN).

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in Security log (7045 service installs, 4720 account creation, 4732 group changes) and IIS/HTTP.sys logs for web-facing roles; scheduled-task store in C:\Windows\System32\Tasks; run `Get-WinEvent -FilterHashtable @{LogName='System'; Id=7045} | Select-Object -First 20 TimeCreated, Message` then `Get-Service | Where-Object {$_.Status -eq 'Running'} | ForEach-Object { Get-CimInstance Win32_Service -Filter "Name='$($_.Name)'" | Select-Object Name, PathName, StartName }`.
3. **Analyze.** Determine the escape primitive: misconfiguration (privileged, hostPath, hostPID) versus kernel CVE — the fix differs. Then: Assess node compromise: if escaped, the node is hostile — cordon, drain, and rebuild it; do not trust in-place cleaning.
4. **Contain and harden.** Never run privileged containers; drop capabilities, use read-only root filesystems, and enforce via admission controllers (OPA/Kyverno). Asset layer: Server Core installs where possible; disable unnecessary roles and SMBv1; enforce SMB signing. Environment layer: Consistent identity (single IdP) across on-prem and cloud; no parallel credential stores.
5. **Document and improve.** Feed incident lessons back into detection-as-code within one sprint — the playbook is a living document, not a PDF. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Rebuilding the container while the compromised node keeps serving the attacker's workloads.
- Assuming non-privileged means safe — hostPath mounts and capabilities can be equally fatal.

## References
