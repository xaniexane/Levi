# Public API Abuse Defense for Backup Servers in Hybrid Cloud (Optimized Maturity)

## Purpose

Exposed APIs are probed for injection, broken auth, and excessive data exposure. API abuse looks like legitimate traffic at volume — detection needs API-aware logging (endpoint, parameters, auth context), not just web logs. Applies to Backup Servers in Hybrid Cloud at Optimized maturity.

## When to use

- High-rate 4xx/5xx sequences against API endpoints indicating fuzzing, or single clients enumerating object IDs sequentially.
- Authenticated API calls accessing other users' objects (BOLA/IDOR patterns) or returning bulk data far beyond normal use.
- Known attack strings (SQLi, SSTI payloads) in API parameters.
- Lens: Best telemetry: job audit logs + admin-console access logs + integrity-check results. Unified SIEM ingesting both on-prem syslog and cloud audit trails with identity correlation across both.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to Conditional-access and network logs covering the interconnect (ExpressRoute/Direct Connect/VPN).

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in Backup job definitions, run histories, and deletion/retention-change audit entries and Admin console logons and configuration exports; repository credential-change history; run `# conceptually (product CLIs differ):` then `backup-cli jobs list --failed --last 7d`.
3. **Analyze.** Replay the suspect API sessions to determine exactly which records were accessed — the breach scope is the data returned, not the requests made. Then: Check whether the abused endpoint lacks authorization checks versus a credentialed attacker using stolen tokens.
4. **Contain and harden.** Positive-security API gateway policies: schema validation, rate limits per client, and authorization checks on every object reference. Asset layer: Immutable storage, separate admin credentials with MFA, no domain-joined backup console if avoidable. Environment layer: Consistent identity (single IdP) across on-prem and cloud; no parallel credential stores.
5. **Document and improve.** Feed incident lessons back into detection-as-code within one sprint — the playbook is a living document, not a PDF. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- WAF-only defense: most API abuse is semantically valid HTTP that no signature catches.
- Logging without the auth context — you cannot distinguish attack from customer without knowing WHO called.
