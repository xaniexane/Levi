# Public API Abuse Defense for Backup Servers in Remote Workforce (Managed Maturity)

## Purpose

Exposed APIs are probed for injection, broken auth, and excessive data exposure. API abuse looks like legitimate traffic at volume — detection needs API-aware logging (endpoint, parameters, auth context), not just web logs. Applies to Backup Servers in Remote Workforce at Managed maturity.

## When to use

- High-rate 4xx/5xx sequences against API endpoints indicating fuzzing, or single clients enumerating object IDs sequentially.
- Authenticated API calls accessing other users' objects (BOLA/IDOR patterns) or returning bulk data far beyond normal use.
- Known attack strings (SQLi, SSTI payloads) in API parameters.
- Lens: Best telemetry: job audit logs + admin-console access logs + integrity-check results. EDR on every endpoint as the primary sensor (no corporate network tap for remote hosts).

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to VPN/ZTNA access logs and SaaS/IdP sign-in logs as the network-visibility substitute.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in Backup job definitions, run histories, and deletion/retention-change audit entries and Admin console logons and configuration exports; repository credential-change history; run `# conceptually (product CLIs differ):` then `backup-cli jobs list --failed --last 7d`.
3. **Analyze.** Replay the suspect API sessions to determine exactly which records were accessed — the breach scope is the data returned, not the requests made. Then: Check whether the abused endpoint lacks authorization checks versus a credentialed attacker using stolen tokens.
4. **Contain and harden.** Positive-security API gateway policies: schema validation, rate limits per client, and authorization checks on every object reference. Asset layer: Immutable storage, separate admin credentials with MFA, no domain-joined backup console if avoidable. Environment layer: Zero-trust access: device compliance + MFA per application, not per network.
5. **Document and improve.** Pre-authorize low-risk containment (host isolation, session revoke, password reset) in the SOAR playbook with full audit logging. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- WAF-only defense: most API abuse is semantically valid HTTP that no signature catches.
- Logging without the auth context — you cannot distinguish attack from customer without knowing WHO called.
