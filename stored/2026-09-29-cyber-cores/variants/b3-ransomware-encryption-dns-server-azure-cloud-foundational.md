# Ransomware Encryption Defense for DNS Servers in Azure Cloud (Foundational Maturity)

## Purpose

Ransomware encrypts files and demands payment, usually after days of dwell time spent disabling recovery. Speed of isolation decides whether you lose one host or the fleet. Never pay without a deliberate, documented decision process. Applies to DNS Servers in Azure Cloud at Foundational maturity.

## When to use

- EDR fires on mass file rename/extension changes, vssadmin delete shadows, bcdedit recovery disabling, or known ransomware process names within seconds of each other.
- Ransom notes (README, DECRYPT files) appearing in multiple directories, wallpaper changes, or a sudden burst of encrypted file extensions across shares.
- Precursor activity in the prior 72 hours: disabled EDR tamper protection, cleared event logs, or backup job failures and backup-server logons from unusual accounts.
- Lens: Best telemetry: query logs (or passive DNS) + zone-transfer/change audit + resolver cache stats. Activity Log and Entra sign-in/audit logs streamed to Log Analytics/SIEM; Defender for Cloud alerts.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to NSG flow logs and storage analytics for data-plane visibility.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in DNS query logs showing tunneling/DGA patterns; zone files and their change history and Zone-transfer (AXFR) request logs; DNSSEC validation failure logs; run `grep -E '.{60,}' /var/log/named/query.log | tail -20   # long labels: tunneling/DGA` then `rndc status; echo ---; journalctl -u named --since '1 hour ago' | grep -iE 'transfer|denied|error' | tail -15`.
3. **Analyze.** Identify the variant from the note text, extension, and ransom portal; check public decryptor availability before any recovery decision — some variants have free decryptors. Then: Reconstruct the entry vector (phishing, exposed RDP/VPN, software vulnerability) and the dwell timeline: first access, privilege escalation, backup targeting, detonation.
4. **Contain and harden.** Immutable, offline-tested backups with alerting on backup tampering; network segmentation so one host cannot reach all shares. Asset layer: Restrict recursion to internal clients, block outbound port 53 except resolvers, DNSSEC validation on. Environment layer: Azure Policy deny-effects on risky configurations; PIM-gated subscription roles.
5. **Document and improve.** Define one escalation trigger in advance (e.g., confirmed credential theft, more than 3 hosts) that moves the case from analyst to incident commander. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Rebuilding from backups that the attacker already found and poisoned — verify backup integrity and isolation first.
- Paying the ransom without confirming the decryptor works and without legal/regulatory review of sanctions exposure.
