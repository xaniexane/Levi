# Group Policy Abuse Defense for EDR Consoles in Air-Gapped Networks (Foundational Maturity)

## Purpose

Group Policy deploys to every machine in scope — including attacker-planted scheduled tasks, scripts, and software. A malicious GPO is a domain-wide persistence and execution platform; monitor GPO changes like code deployments. Applies to EDR Consoles in Air-Gapped Networks at Foundational maturity.

## When to use

- 5136/5137 directory-service changes creating or modifying GPOs, especially new immediate scheduled tasks, startup scripts, or software installation policies.
- SYSVOL replication of unexpected scripts/executables, or GPO version number jumps without a change ticket.
- Mass host behavior change correlating with GP refresh cycles (new persistence appearing fleet-wide simultaneously).
- Lens: Best telemetry: raw process/network telemetry + detection history + sensor health inventory. Local SIEM/log collector inside the enclave (no cloud shipping); removable-media transfer logs.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to Strict allowlisting logs: every binary execution recorded, since the set is small and known.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in Full process trees with command lines, hashes, and network connections for suspect hosts and Detection and response action history (isolations, kills, quarantines); run `# conceptually (EDR APIs differ):` then `edr-cli hunt process --hostname <host> --since 24h --tree`.
3. **Analyze.** Inspect the GPO's full settings and linked scripts; determine the deployment scope (which OUs) to size the affected fleet. Then: Check GPO backup/version history to find when the malicious change was introduced and by whom.
4. **Contain and harden.** Restrict GPO edit rights to a break-glass group, require change tickets, and alert on any GPO modification in real time. Asset layer: Tamper protection locked with console-only disable, auto-isolation policies for high-severity detections. Environment layer: Data diodes or strictly controlled one-way transfers; media sanitization procedures for anything crossing.
5. **Document and improve.** Define one escalation trigger in advance (e.g., confirmed credential theft, more than 3 hosts) that moves the case from analyst to incident commander. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Deleting the malicious GPO without removing the persistence it already deployed to thousands of hosts.
- Missing GPO-based deployment because you hunted only local persistence mechanisms.
