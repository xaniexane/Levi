# Token Impersonation Defense for Firewall Appliances in Colocation Facilities (Managed Maturity)

## Purpose

Attackers steal or duplicate Windows access tokens to act as another user — often SYSTEM — without knowing any password. EDR sees odd parent/child relationships and token-privilege enabling that legitimate software rarely performs. Applies to Firewall Appliances in Colocation Facilities at Managed maturity.

## When to use

- Processes enabling SeDebugPrivilege or SeImpersonatePrivilege outside of known admin tooling, or unexpected token duplication API sequences in EDR telemetry.
- A low-privilege process spawning children as SYSTEM or as another logged-on user without a legitimate service path.
- Named-pipe impersonation patterns (PrintSpooler-style) from non-printer processes.
- Lens: Best telemetry: traffic/deny logs + admin audit log + config-change diffs shipped to SIEM. Customer-owned network taps and logging (the colo provider's logs are out of scope — verify contractually).

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to Badge/physical access logs from the facility correlated with remote-hand ticket times.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in Traffic logs (allowed/denied with rule IDs), threat logs (IPS/AV verdicts), admin audit log and Configuration revisions and diffs; VPN session logs and authentication failures; run `# vendor CLIs differ; conceptually:` then `show log traffic query (source <suspect-ip>)             # Palo Alto style`.
3. **Analyze.** Trace the token source: which process's token was stolen, and did that source process itself get compromised first? Then: Check what the impersonated context accessed — file, registry, and network actions taken as the victim identity.
4. **Contain and harden.** Remove SeImpersonatePrivilege from service accounts that do not need it; patch print-spooler-class vulnerabilities promptly. Asset layer: Default-deny with documented rules, admin on dedicated interface with MFA, config backups versioned. Environment layer: Locked cabinets, private cages, and escort policies for remote hands.
5. **Document and improve.** Pre-authorize low-risk containment (host isolation, session revoke, password reset) in the SOAR playbook with full audit logging. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Assuming token theft requires admin — some impersonation primitives work from lower privilege.
- Missing that a stolen token can be replayed on OTHER hosts via remote authentication.
