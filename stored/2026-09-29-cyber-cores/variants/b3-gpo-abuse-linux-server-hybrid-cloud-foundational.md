# Group Policy Abuse Defense for Linux Servers in Hybrid Cloud (Foundational Maturity)

## Purpose

Group Policy deploys to every machine in scope — including attacker-planted scheduled tasks, scripts, and software. A malicious GPO is a domain-wide persistence and execution platform; monitor GPO changes like code deployments. Applies to Linux Servers in Hybrid Cloud at Foundational maturity.

## When to use

- 5136/5137 directory-service changes creating or modifying GPOs, especially new immediate scheduled tasks, startup scripts, or software installation policies.
- SYSVOL replication of unexpected scripts/executables, or GPO version number jumps without a change ticket.
- Mass host behavior change correlating with GP refresh cycles (new persistence appearing fleet-wide simultaneously).
- Lens: Best telemetry: auditd + centralized syslog/journald + osquery or an EDR agent. Unified SIEM ingesting both on-prem syslog and cloud audit trails with identity correlation across both.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to Conditional-access and network logs covering the interconnect (ExpressRoute/Direct Connect/VPN).

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in auth.log/secure (SSH logons), auditd logs (execve, file writes), and cron tables (/etc/crontab, /etc/cron.d/*, user crontabs) and systemd unit files in /etc/systemd/system/ and SSH authorized_keys files for all users; run `sudo grep -E 'Failed|Accepted' /var/log/auth.log | tail -40` then `sudo ausearch -m EXECVE --start recent -i | grep -E 'curl|wget|bash|sh|python|perl' | tail -30`.
3. **Analyze.** Inspect the GPO's full settings and linked scripts; determine the deployment scope (which OUs) to size the affected fleet. Then: Check GPO backup/version history to find when the malicious change was introduced and by whom.
4. **Contain and harden.** Restrict GPO edit rights to a break-glass group, require change tickets, and alert on any GPO modification in real time. Asset layer: Key-only SSH (no passwords), fail2ban or equivalent, unattended security updates enabled. Environment layer: Consistent identity (single IdP) across on-prem and cloud; no parallel credential stores.
5. **Document and improve.** Define one escalation trigger in advance (e.g., confirmed credential theft, more than 3 hosts) that moves the case from analyst to incident commander. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Deleting the malicious GPO without removing the persistence it already deployed to thousands of hosts.
- Missing GPO-based deployment because you hunted only local persistence mechanisms.

## References
