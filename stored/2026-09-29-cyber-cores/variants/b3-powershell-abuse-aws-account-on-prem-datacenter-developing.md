# Malicious PowerShell Abuse Defense for AWS Accounts in On-Premises Datacenter (Developing Maturity)

## Purpose

PowerShell is the attacker's Swiss-army knife: encoded commands, in-memory execution, credential theft, lateral movement. Deep script-block and module logging turns it from a blind spot into one of your richest telemetry sources. Applies to AWS Accounts in On-Premises Datacenter at Developing maturity.

## When to use

- Event 4104 (script block logging) with encoded commands (-enc/-e), Invoke-Mimikatz/Invoke-Shellcode patterns, or obfuscation (heavy string concatenation, char codes).
- PowerShell spawned by Office, browsers, or WMI with hidden window styles, or AMSI bypass patterns in the script text.
- Module logging showing credential-access or AD-enumeration cmdlets from non-admin workstations.
- Lens: Best telemetry: CloudTrail (org trail, all regions) + GuardDuty + VPC flow logs + Config. Full network tap/SPAN coverage at core and distribution layers feeding IDS and full-packet capture.

## Prerequisites

- Written authorization from the asset owner and incident commander before active containment.
- Access to Centralized syslog from all infrastructure with NTP-synced timestamps for cross-device correlation.

## Procedure

1. **Authorize and scope.** Open a ticket, confirm written authorization, and preserve evidence before changing anything.
2. **Detect and collect.** Hunt the signals above in CloudTrail event history (console logons, IAM changes, AssumeRole, security-group changes) and GuardDuty findings, IAM Access Analyzer results, and S3 server-access logs for data stores; run `aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=ConsoleLogin --max-items 20` then `aws iam generate-credential-report && aws iam get-credential-report --query Content --output text | base64 -d | head -5`.
3. **Analyze.** Decode every obfuscated layer — the final script reveals the true objective (many 'downloaders' are actually ransomware staging). Then: Correlate the PowerShell session with its parent to find the delivery vector (macro, scheduled task, remote session).
4. **Contain and harden.** Enable script-block logging, module logging, and transcription fleet-wide; forward to the SIEM with alerting. Asset layer: MFA on root + all IAM users, SCPs denying logging disablement and unapproved regions, no long-lived keys. Environment layer: Physical access controls with badge logs correlatable to logical access during investigations.
5. **Document and improve.** Assign RACI for each procedure step (who detects, who contains, who communicates) and rehearse it quarterly. Record the timeline, indicators, actions taken, and lessons learned.

## Expected outputs

- Scoped timeline; affected assets, accounts, and data with containment status each.
- Hardening verified effective; detection improvements filed.

## Pitfalls

- Logging PowerShell without a SIEM pipeline to analyze it — 4104 events are high-volume and useless unsearched.
- Assuming -noprofile -w hidden is always malicious; admins use it too — baseline first.
